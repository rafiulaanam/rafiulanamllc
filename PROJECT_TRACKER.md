## Findings that affect launch

- **Hosted Supabase** — The website migration has been applied. All nine application tables have row-level security. Public reads, seed content, and the local site connection were verified. Personal administrator sign-in and Vercel acceptance remain open.
- **Admin sessions** — The server clients inherit the installed Supabase SSR default `httpOnly: false`. Verify cookie attributes over HTTPS and harden the server-only session flow before granting production admin access. See `N04`.
- **Media visibility and cleanup** — The public bucket can serve a draft or detached object to anyone who has its URL. Uploads precede database mutations, so failed saves and image replacement can leave unreferenced public objects. See `M06` and `M07`.
- **Launch content** — The local site has an empty catalogue, pending official business links, illustrative business imagery, and no verified corporate phone, email, or social profiles. See `D06`, `G06`, `H03`, `I03`, `J02`, and `U05`.
- **Shared server credential** — Rotate the server secret shared in chat and store its replacement in the appropriate secret manager. Audit requests used the publishable key only. The application’s public/server-session integration uses the publishable key and does not require the server secret.
